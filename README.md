# nodepool

从公开 gist 聚合免费代理节点 → 多轮 HTTPS 测活 → 可选查询 [IPPure](https://ippure.com/) 参考评分 →
维护节点池 → 生成并发布 Clash/mihomo 订阅。一次运行跑完整条流水线。

## 快速开始

```bash
python -m pip install -r requirements.txt
python update.py                 # 跑完整流程（采集 + 测试 + 生成 + 发布）
python update.py --no-publish    # 只生成本地文件 output/clash.yaml，不发布
python update.py --skip-collect  # 不采集新节点，只复测现有池
python update.py --pages 5       # 覆盖搜索页数
python update.py --max-candidates 400
```

首次运行会自动把 mihomo 内核下载到 `bin/mihomo.exe`。
Linux 下载到 `bin/mihomo`。建议使用 Python 3.12 或更新版本。

## 稳定节点池

节点池会跨运行积累记录，而不是每次重建。旧版 `data/pool.json` 会自动迁移，保留已知的
连通性与评分，但不会把只有一次成功记录的旧节点直接当作稳定节点。

- 默认连续 5 次运行测活成功、最近最多 20 次测活成功率至少 80%，
  才晋升稳定池；通过验证的稳定节点进入 `🛡️ 稳定节点` 代理组。
- 稳定节点短暂失败时暂停输出，保留身份和测试历史。只有连续失败至少 12 次且距离最后
  成功已超过 7 天，才进入 24 小时冷却；冷却后仍可复测恢复。
- 普通节点连续失败 3 次后也先冷却，重新采集相同节点不会清空失败历史。
- 每轮至少预留 25% 的候选配额给未验证、从未连通节点，其余节点按最久未测
  轮转。历史可用节点不会占满所有新节点探索名额。
- 未轮到本轮复测的节点，可以在最近测活 12 小时有效期内继续输出；已复测失败的节点不输出。
  评分高、缺失或过期均不会阻止默认策略下的入选与晋升，稳定身份也不会绕过连通性检查。
- 节点池达到容量上限时优先保留稳定节点；陈旧清理按来源最后出现时间计算。

这些阈值在 `config.yaml` 的 `pool`、`purity` 和 `output` 中配置。

## GitHub Actions

在仓库的 Actions secrets 中设置：

- `GIST_TOKEN`：有 Gists 读写权限的个人 token。
- `GIST_ID`：固定 **secret gist** 的 ID。可先在本地运行一次创建订阅，再从
  `data/gist.json` 获取 ID。云端缺少固定 ID 时不会自动新建 gist，以免缓存丢失后换链接。

定时工作流每 3 小时执行一次，也支持手动触发；GitHub 的调度可能延迟或跳过，不能当作
严格定时器。工作流会恢复节点池与内核缓存，并在更新失败时尽力保存已完成的节点池阶段。
固定订阅地址由 `GIST_ID` 提供，不依赖缓存中的 Gist 状态文件。缓存路径继续使用 `data`，
以兼容恢复旧版运行积累的节点池。

发布订阅时会同时把稳定节点及其历史保存到同一 secret gist 的 `stable-pool.json`；
缓存缺失时可恢复稳定池，缓存较旧时也会合并较新的远端记录。没有合格订阅时只更新稳定池
备份，不修改订阅文件。远端备份损坏或不可访问且本地池为空时，会停止更新以保护历史。
尚未晋升的探索节点仍依赖 Actions 缓存。本地写入为原子替换，并保留
`data/pool.json.bak` 供损坏时恢复。

## 失败处理与验证

- 没有合格节点时保留已有本地订阅和 Gist，不发布空结果。
- 默认不查询评分；开启可选查询后，查询失败不会阻止连通节点输出，空评分不获得缓存。
- 发布网络失败会重试，并以非零状态退出；已经完成的节点池结果仍会保存。
- 固定 Gist 不存在、不可访问或是 public gist 时停止发布，不自动换地址。
- 采集与纯净度检测均有软时间预算，未完成的节点留待后续运行。
- 默认经每节点独立监听轮换请求 Google 和 Cloudflare 的 HTTPS 地址，4 轮至少通过 3 轮。
  使用真实 GET、验证 TLS 证书、核验 HTTP 204、不跟随跳转，不只读取内核测速毫秒数；
  仅能访问单个测速地址的节点不算合格。每轮重新建连接，避免复用掩盖握手失败。
- 检测目标、状态码或门槛变化后，旧结果保留为历史，复测符合当前策略后才重新输出或晋升。
- 同一工作目录禁止两个更新进程同时写池，mihomo 临时目录在结束时清理。

退出码：`0` 成功，`1` 运行异常，`2` 配置错误或空池，`3` 发布失败/缺少 token，
`4` 无合格节点并保留原订阅，`130` 用户中断。

运行回归测试：

```bash
python -m unittest discover -s tests -v
```

测试不访问真实 Gist 或代理节点。检测到本地 mihomo 时还会进行配置检查与进程生命周期测试。

## 配置 GitHub Token（发布订阅需要）

在项目根目录建一个 `.env` 文件，写入（**不要提交到 git，不要分享**）：

```
GITHUB_TOKEN=github_pat_xxx
```

Token 只需勾选 **gist** 权限（classic token 勾 `gist`，或 fine-grained token 授予
Gists 读写）。它同时用于：
- 读取 gist 内容（授权后额度 5000 次/小时，远高于未授权的 60 次）；
- 创建 / 更新存放订阅的 **secret gist**。

首次发布会自动创建一个 secret gist 并把它的 id 记到 `data/gist.json`，之后每次更新同一个
gist，**订阅链接固定不变**。

## 在客户端里用

生成的订阅是 mihomo 格式，适用于 **Clash Verge Rev / FlClash / Mihomo Party** 等
mihomo 内核客户端（旧版 Clash for Windows 不支持 vless）。

- 导入订阅链接后，务必在客户端打开 **“通过代理更新订阅”**，因为链接在
  `gist.githubusercontent.com` 上，国内直连通常失败。
- 代理组：`🔰 手动选择`（总入口）/ `♻️ 自动选择`（优先低延迟，50ms 切换容差）/ 以及按纯净度分的
  `极度纯净` `纯净` `中性` 三个参考评分组；更高分及未评分节点进入 `其他节点`。
  稳定池积累起来后会出现 `🛡️ 稳定节点` 组，节点输出顺序优先稳定身份、历史成功率和延迟。
  手动组也可以直接选择单个节点，中国 IP 和局域网走直连。

订阅将节点服务器域名与目标网站的 DNS 解析分开：节点域名使用可直连的加密 DNS，
境外网站通过自动组查询加密 DNS，国内直连域名使用国内解析器。
OpenAI、Google、GitHub 等域名规则优先于中国 IP 直连规则，避免错误解析的中国 IP
把境外网站送去直连。自动组使用 HTTPS 健康检查；纯净度描述出口 IP，不代表连通性或网速。

GitHub 检测和客户端检测发生在不同网络，结果可能不同。节点名称中的延迟是生成订阅时的
云端测量值；实际使用以本机 Clash 的实时检测为准。全部候选失效时，自动选择也无法恢复
不可达的服务器；节点池会保留历史并在后续更新中复测。

## 本机验证后发布

如果云端通过的节点在本机大量超时，可在实际使用订阅的电脑运行：

```powershell
python verify.py --core D:\Application\Clash-verge\verge-mihomo.exe
# 只测试本地文件、不发布：
python verify.py --input output/clash.yaml --no-publish
# PowerShell 覆盖为空代理时使用 --proxy=，避免旧版 PowerShell 丢失空参数。
```

默认从固定 secret gist 下载 `candidates.yaml`，旧订阅没有候选文件时读取 `clash.yaml`。
检测在隔离内核中执行，不切换正在使用的 Clash 订阅。先要求全部四轮 HTTPS 成功，
再验证 GitHub、ChatGPT 的公开测试页面均返回 200，最后要求第二轮四次 HTTPS 全部成功。
检测失败节点不会因为纯净度高而放行；服务页面受限制的节点也会被保守排除。

成功发布时，`clash.yaml` 和 `client-health.json` 在同一个 Gist 请求中更新，固定订阅地址不变。
本机报告启用白名单后，云端输出须同时通过云端检测与本机白名单；未知或本机失败的节点
只进入候选文件，不会在下一次云端更新中重新混进订阅。节点身份按实际连接参数计算，
改显示名称不会绕过筛选，也不会删除稳定池历史。没有本机报告的项目维持独立云端运行。

本机证明默认有效 7 天，云端仍要求自身测活在 12 小时内有效；默认不要求评分有效期。
请在同一使用网络中定期运行 `verify.py` 刷新证明并测试新候选。它是一次性命令，不会
安装后台任务；本机报告过期或没有交集时，云端保留原订阅，继续更新可复测候选及稳定池备份。
报告损坏、不可读或已启用的报告文件丢失时，直接停止发布，防止静默关闭本机筛选。
已经发布的节点仍可能随网络或服务变化失效，客户端自动组继续实时检查并切换。

## 纯净度分级（IPPure 系数，越低越纯净）

| 系数区间 | 名称 |
|---|---|
| 0–14 | 极度纯净 |
| 15–24 | 纯净 |
| 25–40 | 中性 |

评分仅作参考，不影响默认策略的入选、稳定池晋升或候选优先级。默认配置为
`purity.enabled: false`、`purity.required: false`，不查询 IPPure，也不因评分高、缺失或过期淘汰节点。
如需显示新评分，可单独开启 `purity.enabled: true`，查询失败仍不阻止发布；
只有显式设置 `purity.required: true`，才重新启用 `purity.max_score` 和评分有效期限制。
兼容旧配置：未写这两个开关的旧配置保留原评分筛选行为。

## 工作目录

```
update.py          入口
verify.py          本机严格复测与白名单发布
config.yaml        所有参数
.env               你的 GitHub token（自建，git 忽略）
bin/mihomo.exe     内核（自动下载）
data/pool.json     节点池（持久化，记录测活历史、稳定身份及最近纯净度结果）
data/gist.json     已发布 gist 的 id
data/client-health.json  已发布本机验证白名单
output/clash.yaml  订阅文件本地副本
output/candidates.yaml 云端候选，不直接导入客户端
```

## 注意

- 免费公开节点随时可能失效、被滥用、被限速，“纯净”也只是某一时刻的快照。要稳定可用，
  还是自建 VPS 最可靠。
- 节点主人能看到你经由它访问了哪些站点，**不要用免费节点登录重要账号或传输敏感信息**。
- IPPure 参考接口异常时，默认策略仍按连通性和稳定性正常输出；显式启用评分筛选后才会
  要求有效且未超标的评分。
- 脚本对 gist 访问做了节流；大幅调高 `search.pages` 或调低 `page_delay` 可能触发
  GitHub 限流。
